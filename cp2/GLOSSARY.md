# CP2 용어집 (2차)

CP2 문서·코드·로그에 나오는 말을 한곳에 모았다. 각 항목은 **뜻** → **게임으로 치면** → **어디에**(코드·파일) 순서다.
비슷한 말이 여럿일 때 이 문서의 말을 표준으로 쓴다. 1차 시도와 뜻이 바뀐 말은 ★로 표시했다.

## 1. 시간과 시계

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **정규 곡 시간** | 곡 시작을 0으로 하는 i64 나노초. 채보·소리·판정이 모두 이 하나의 시간을 쓴다 | 악보의 "몇 초 지점" | `runtime.rs` |
| **QPC** | Windows 고해상도 시계의 눈금 (이 PC에서 1초 = 10,000,000) | 컴퓨터의 벽시계 | `synchronizer::qpc` |
| **장치 시계 A** | 오디오 장치가 보고하는 "지금 몇 번째 프레임을 내는 중"을 QPC에 맞춘 직선 | 소리가 지금 어디까지 나갔는지 아는 시계 | `SharedClock` (CP1) |
| **시간축** (timeline) | 믹서가 소리를 놓는 프레임 번호. 오디오 정지 때 건너뛴 만큼 장치 위치와 차이(offset)가 생기지만 끊기지 않는다 | 곡이 흐르는 자 | `ContentSkip::timeline` |
| **기록 시계 C** ★ | C = A + D. 판정·화면·음악 예약·키음 예약이 모두 쓰는 하나의 시계. 1차 시도의 "현재 = 출력 위치"를 대신한다 | 게임의 "지금" | [설계](../design/기록%20시계%20설계.md), `audio.rs` |
| **D** | 요청 → 그 소리를 놓을 수 있는 가장 이른 시간축 위치까지의 여유. 경로마다 리드인 동안 잰 최대 + 2 ms (ms 올림), 플레이 중 고정 | 키음 예약의 "앞당김 여유" | `AudioMonitor.d_frames`, `--d-ms` |
| **필요 (need)** | 블록마다 잰 "직전 블록이 요청을 꺼낸 순간의 장치 위치 → 이 블록의 시작". D를 정하는 원재료 | — | `BlockLog.need`, HUD "필요 최대" |
| **origin** | 곡 시간 0이 놓이는 시간축 프레임 (리드인 뒤). 음악은 origin + D + T에 놓인다 | 곡이 시작되는 칸 | `meta.json` |
| **콘텐츠 건너뜀** ★ | 오디오가 멈췄다 돌아오면 장치 위치가 시계 직선보다 뒤처진다. 2 ms 넘게 뒤처지면 그만큼 시간축을 앞으로 건너뛰어(소리 내용을 버림) 시간축이 실제 시간과 같게 흐르게 한다. ASIO는 장치 위치가 그대로 흘러 필요 없음 | 소리가 끊긴 만큼 노래가 앞으로 넘어가서, 화면·판정·노래가 계속 같은 자리 | `ContentSkip`, 렉 사건 `콘텐츠 건너뜀` |
| **epoch / 시계 점프** | 장치 시계 직선의 세대 / 새 세대로 바뀌며 같은 순간의 위치가 튄 양. 우리 방식에선 건너뜀이 흡수해서 점프가 생기지 않는다 (배타 모드 1회 예외, 0.21 ms) | 음악이 갑자기 밀린 양 | 렉 사건 `시계 점프` |
| **프로필 시계** | 프레임 구동 프로필이 프레임마다 정하는 자기 곡 시각. 봇이 그 게임 화면을 보고 치는 사람처럼 이 시각을 따른다 | 그 게임 화면에 보이는 "지금" | `bot::ProfileClock` |

## 2. 소리

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **자동재생 / 반주** | 플레이어 입력과 무관하게 정해진 시각에 울리는 소리 | BGM·배경 키음 | `chart.auto` |
| **키음** | 플레이어가 노트를 칠 때 울리는 그 노트의 소리 | 버튼 소리 | `note_sounds` |
| **긴 소리 / 짧은 소리** | 2초 넘는 소리 / 그 이하. Unshakable은 16~54초짜리 스템이 131개 | 반주 트랙 / 효과음 | `LONG_SOUND_NS` |
| **믹서** | 실행 데이터와 키음 요청을 시간축에 섞는 코드. 오프라인 렌더와 실시간이 같은 코드 | 소리를 내는 엔진 | `mixer.rs` |
| **NOW 요청** | 예정 프레임 대신 "받은 블록 맨 앞에서 시작" (프레임 구동 프로필의 즉시 재생) | "지금 울려" | `mixer::NOW` |
| **늦은 키음 정책** | 키음 요청이 예정 프레임을 지나 도착하면 처음부터 내되, 100 ms 넘게 늦으면 버림 | 정지 중 친 키음이 한참 뒤에 "띵" 하지 않게 | `--late-drop-ms` |
| **오디오 경로** | WASAPI 공유 · WASAPI 배타(5 ms 주기) · ASIO(64샘플). 같은 소리 코어를 쓴다 | 소리 출력 방식 설정 | `AudioPath`, `--audio` |
| **루프백** | 장치 출력을 장치 입력으로 되돌려 녹음한 것 (실제로 나간 소리의 증거) | — | `capture_*` |

## 3. 입력과 판정

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **입력 도장** | 키가 실제로 눌린 QPC 추정값 (Raw Input, 큐가 빈 마지막 순간보다 앞으로 가지 않게 자름) | 버튼을 누른 순간 | `input.rs` `floor_qpc` |
| **판정 오차** ★ | C(누른 순간) − 노트 시간 (+면 늦음). 1차 시도는 "그 순간 들리는 곡 시간" 기준이었다 | 빠름 / 늦음 | `judging.rs` |
| **화면 오프셋** ★ | 노트를 그리는 위치만 옮기는 값 (+면 미리 그림). 판정·키음·봇은 그대로. 예전 `--out-offset-ms`(판정만 옮겨 "PERFECT = 키음이 반주 위"를 깨뜨림)를 대신한다 | 모니터 지연 보정 | `--display-offset-ms` |
| **판정 창** | PERFECT ±20 / GREAT ±50 / GOOD ±100 / BAD ±150 ms (CP2 임시값) | 판정 범위 | `Windows::CP2` |
| **PERFECT 키음 = 반주** | 판정 오차 0이면 키음이 C(누른 순간) + D = 반주가 놓인 같은 샘플에 놓인다. 키음 vs 반주 = 판정 오차 | 정확히 치면 키음이 반주에 딱 붙음 | — |
| **리플레이** | 기록된 입력만으로 판정을 다시 해 실행 중 판정과 맞대기. 우리 방식만 (재현 100%) | 같은 플레이 다시 재생 | `replay.exe` |

## 4. 렉 감지와 고장

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **고장 주입** | 일부러 스레드를 재워 렉을 만드는 것: 오디오 · 화면 · 판정 · 입력 | 렉 시험 | `--faults 종류@곡초:ms`, F1~F4, + / − |
| **감시 스레드** | 1 ms마다 각 스레드의 맥박과 오디오 상태를 보고 렉 사건을 기록 | 렉 감지기 | `monitor.rs`, `lag_events.csv` |
| **렉 사건** | 오디오 정지 · 언더런 · 시계 점프 · 화면 정지 · 판정 정지 · 입력 정지 · 상태 · 재동기화 완료 · 콘텐츠 건너뜀 | — | `LAG_NAMES` |
| **상태** ★ | Running / Suspect(경로가 멈춘 동안) / Resyncing(진짜 시계 점프 때만. 우리 방식은 건너뜀으로 점프가 없어 거의 안 들어감) | 게임이 스스로 아는 "지금 정상인가" | `MonitorShared.state` |
| **손실** | PERFECT인데 키음을 제자리에 낼 수 없었던 누름: 버림 + 늦게 놓임. 정지 중에 누른 노트라 물리적으로 불가능 | 렉 동안 친 노트의 소리가 빠짐 | `analyze_v2.py` |

## 5. 프로필

| 용어 | 뜻 |
|---|---|
| **우리 방식** (`ours`) | 기록 시계 C 하나. 음악·키음 모두 샘플 단위 예약, 오디오 정지는 콘텐츠 건너뜀 |
| **프레임 구동** | 화면 프레임마다 그 프로필의 시계로 지난 자동재생과 키음을 NOW로 울리고 판정하는 방식. D = 0, 오디오 정지는 건너뛰지 않음(멈춘 곳에서 이어서 냄). 아래 셋 |
| **IIDX 개량형** (`iidx`) | 틱 = 화면 갱신. 오디오와 비교해 데드밴드(−17~+34 ms) 밖이면 빠르게·느리게 따라잡음 |
| **DJMAX식** (`djmax`) | 프레임 경과 시간을 더하되 한 번에 최대 0.333초, 판정은 200 Hz 고정 스텝 |
| **BMS식** (`bms`) | 시작 후 흐른 벽시계 시간 그대로, 1 kHz 입력 폴링, 같은 소리 재트리거 때 끊기 |

## 6. 지표

| 지표 | 뜻 | 게임으로 치면 |
|---|---|---|
| **키음 vs 반주 (새 소리)** | PERFECT 누름의 키음이 놓인 프레임 − 같은 곡 시각의 반주 프레임. 반주는 그 시각 앞뒤 2초 안에 실제로 시작한 자동재생들을 곡 시각으로 보간 | 키음과 방금 울린 반주가 맞는가 |
| **키음 vs 반주 (긴 소리)** | 같은 값을, 그 순간 이미 울리고 있던 긴 소리들 각각의 해당 위치로 잰 것 중 가장 크게 어긋난 값 | 키음과 렉 전부터 깔려 있던 스템이 맞는가 |
| **5 ms 넘음** | 위 두 값 중 하나라도 5 ms 넘게 어긋난 PERFECT 개수 | 들리는 어긋남 |
| **잔차** | 키음 vs 반주 − 판정 오차. 판정이 "맞다"고 한 만큼 키음이 반주에 맞았는가 (우리 방식 ±0.01 ms) | 판정을 믿어도 되는가 |
| **무결성** | 믹서 기록으로 재구성한 출력과 루프백 녹음을 1초 창마다 맞대어 어긋남이 곡 내내 상수인지 | 기록이 실제 소리와 같은가 |
| **고장 구간** | 고장마다 그 뒤 10초 안의 PERFECT 누름으로 다시 센 지표 | — |
| **봇** | PERFECT 순간에 OS 입력(F24)을 넣는 측정용 플레이어. 우리 방식은 C를, 프레임 구동은 그 프로필 시계를 따른다 | 기계 손 |

| **도장 − 실제 누름** | 게임이 기록한 누른 시각 − 봇이 SendInput을 부른 시각 (봇 실행에서만) | 입력 시각 기록이 맞나 | `analyze_v2.py`, 2-5 표 |
| **하한 나이** | 입력 스레드가 메시지를 받은 시각 − 큐가 비어 있음을 마지막으로 본 시각. 크면 도장 추정이 한 틱(약 15.6 ms)만큼 이르게 나올 수 있다 | — | `judgments.csv` `q_recv`·`q_floor` |
