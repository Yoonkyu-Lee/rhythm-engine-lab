# CP2 용어집

CP2 문서·코드·로그에 나오는 말을 한곳에 모았다. 각 항목은 **뜻**(한 줄) → **게임으로 치면**(플레이 입장) → 필요하면 **어디에**(코드·파일) 순서다.
비슷한 말이 여럿일 때 이 문서의 말을 표준으로 쓴다.

## 1. 시간과 시계

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **정규 곡 시간** | 곡 시작을 0으로 하는 i64 나노초. 채보·소리·판정이 모두 이 하나의 시간을 쓴다 | 악보의 "몇 초 지점" | `runtime.rs` (`Note.t`, `SoundEvent.t`) |
| **스트림 프레임** | 오디오 출력 스트림에 써 넣은 샘플 프레임의 번호 (48 kHz면 1초 = 48,000) | 스피커로 나가는 소리의 칸 번호 | 믹서 `fill(…, block, …)` |
| **origin** | 곡 시간 0이 놓이는 스트림 프레임 (리드인 2초 뒤) | "곡이 시작되는 칸" | `meta.json` `origin` |
| **QPC** | Windows 고해상도 시계(QueryPerformanceCounter)의 눈금. 이 PC에서 1초 = 10,000,000 | 컴퓨터의 벽시계 | `synchronizer::qpc` |
| **장치 시계** | 오디오 장치가 보고하는 "지금 몇 번째 프레임을 내는 중"을 QPC에 맞춘 직선 (프레임 = a + b·시각) | 음악이 지금 어디까지 흘렀는지 알려 주는 시계 | `SharedClock` (CP1) |
| **epoch** | 장치 시계 직선의 세대 번호. 언더런 등으로 대응이 끊기면 새 epoch가 된다 | "음악 위치를 다시 잡았다" 표시 | `ClockSnapshot.epoch` |
| **시계 점프** | 새 epoch로 바뀌며 같은 QPC에 대응하는 프레임이 튄 양 | 음악이 갑자기 밀린 양 | 렉 사건 `ClockJump` |
| **청취 곡 시간 H(q)** | QPC 시각 q에 귀에 들리는 곡 시간 = (장치 시계로 본 프레임 − origin) / rate + 출력 보정 | "이 순간 들리는 음악이 악보 몇 초 지점인가" | `judging::song_ns` |
| **출력 보정** (`--out-offset-ms`) | 청취 곡 시간에 더하는 상수. 장치 기준점에서 귀까지의 고정 지연을 맞춘다 | 싱크 보정 | `out_offset_ns` |
| **틱** | 프레임 구동 프로필이 차트를 한 칸 넘기는 단위 (IIDX 개량형: 화면 갱신 한 번) | 게임 내부 시계의 한 걸음 | `profiles.rs` |
| **vblank** | 모니터가 한 장을 다 그리고 다음 장으로 넘어가는 순간 (240 Hz면 4.17 ms마다) | 화면 갱신 | DXGI 프레임 통계 |

## 2. 실행 데이터와 소리

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **실행 데이터** (`.rtc`) | 코어가 읽는 유일한 곡 표현. 시간순 배열(자동재생·레인별 노트·화음·스크롤 지도) + PCM 뱅크 하나 | 플레이 직전에 다 풀어 둔 악보와 소리 | `runtime.rs`, `rtc.rs` |
| **PCM 뱅크** | 곡의 모든 소리를 이어 붙인 f32 샘플 덩어리. 소리는 (시작, 길이)로 가리킨다 | 키음 파일 전부를 미리 디코딩해 둔 것 | `SoundBank` |
| **자동재생** | 플레이어 입력과 무관하게 정해진 시각에 울리는 소리 (반주·배경 키음) | BGM과 배경음 | `chart.auto` |
| **키음** | 플레이어가 노트를 칠 때 울리는 그 노트의 소리 (화음이면 여러 개) | 버튼 소리 | `note_sounds` |
| **빈 누름** | 판정 창 안에 노트가 없는 누름. 판정 없이 다음 노트의 소리를 울린다 | 헛치기 | `Judged::Empty` |
| **보이스 / 보이스 예산** | 동시에 울리는 소리 하나 / 그 최대 개수 (동시 발음 최댓값 + 1/4 + 8) | 동시 발음 수 | `Mixer`, `compile` |
| **긴 소리 / 짧은 소리** | 2초 넘는 소리 / 그 이하 (늦음 정책을 가르는 기준) | 반주 트랙 / 효과음 | `LONG_SOUND_NS` |
| **기준 BPM** | 스크롤 속도의 기준이 되는 BPM. 데이터에 명시한다 (구동기가 추정하지 않음) | 하이스피드의 기준 | `ScrollPoint`, `reference_bpm` |
| **리샘플링** | 뱅크(44.1 kHz)를 장치 rate(48 kHz)로 바꿈. 윈도 sinc 다상 필터 (160/147) | — | `resample.rs` |
| **마스터 이득 / 헤드룸** | 곡 전체에 곱하는 배율. 정답 렌더의 최댓값을 −1 dBFS에 맞춰 장치에서 잘리지 않게 한다 | 볼륨 자동 맞춤 | `master_gain` |

## 3. 믹서와 오디오 출력

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **믹서** | 실행 데이터와 키음 요청을 스트림 프레임에 섞는 코드. 오프라인 렌더와 실시간 콜백이 같은 코드 | 소리를 내는 엔진 | `mixer.rs` |
| **블록** | 오디오 콜백 한 번에 채우는 프레임 묶음 (보통 10 ms 안팎) | — | `fill` |
| **예정 프레임** | 소리가 시작되어야 하는 스트림 프레임 | "이 소리는 정확히 여기서" | `due` |
| **늦음** | 요청이 믹서에 도착했을 때 예정 프레임이 이미 지난 양 | 렉 때문에 늦게 온 소리 | `late` |
| **늦음 정책** | 늦은 소리를 어떻게 낼지: 앞부분 자르기(CutFront) / 처음부터(PlayWhole) / 버리기(Drop). 출처별로 다르다 | — | `LatePolicy` |
| **늦은 키음 버리기** | 처음부터 내는 소리도 100 ms보다 늦으면 버림 (CP2 결정) | 렉 동안 친 키음이 한참 뒤에 "띵" 하지 않게 | `drop_after`, `--late-drop-ms` |
| **NOW 요청** | 예정 프레임 대신 "받은 블록 맨 앞에서 시작" (프레임 구동 프로필의 즉시 재생) | — | `mixer::NOW` |
| **재트리거 끊기** | 같은 소리를 다시 울리면 앞 소리를 끊음 (BMS 구동기 방식) | — | `cut_same`, 사건 `Cut` |
| **믹서 사건 로그** | 발음 시작(Start)·버림(Dropped)·풀 넘침(Overflow)·끊김(Cut)의 기록 | 소리의 블랙박스 | `mix_events.csv` |
| **정답 렌더** | 모든 노트를 제때 친 소리를 오프라인으로 만든 것. 블록 크기와 무관하게 비트 단위로 같다 | 렉이 없을 때 들려야 하는 소리 | `render`, `render_perfect` |
| **재구성 스트림** | 믹서 사건 로그로 실제로 나간 스트림을 다시 만든 것 | — | `restream` |
| **루프백** | 장치 출력을 장치 입력으로 되돌려 녹음한 것 (실제로 나간 소리의 증거) | — | `capture_*`, TOPPING Loopback |
| **경로 필터** | 장치·OS 출력 경로의 선형 EQ(고음 +1 dB 정도). 33탭 FIR로 맞춰 빼고 비교한다 | — | `analyze_play.py` |
| **WASAPI 공유 모드** | Windows 오디오 공유 경로. 출력 버퍼 때문에 누름 → 소리에 30~40 ms 하한이 있다 | 키음 지연의 바닥 | `audio.rs` |
| **패딩** | 출력 버퍼에 아직 남은(안 나간) 프레임 수 | — | `audio_blocks.csv` `padding` |
| **언더런** | 버퍼가 비어 장치가 무음을 낸 것. 스트림 전체가 그만큼 뒤로 밀린다 | 소리 끊김 | 렉 사건 `Underrun` |
| **최소 지연 모드** | 키음을 "가장 이른 안전한 프레임"에 처음부터 내는 방식 | — | 설계안 8-3 |

## 4. 입력과 판정

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **입력 도장** | 키 입력이 실제로 눌린 QPC 추정값 (Raw Input + 메시지 시각 역산, 큐가 빈 마지막 순간보다 앞으로 가지 않게 자름) | 버튼을 누른 정확한 순간 | `input.rs` |
| **watermark** | "이 시각 이전의 입력은 다 받았다"는 표시 (입력 큐가 비었다고 확인한 마지막 QPC) | — | `Input.watermark` |
| **판정 창** | 오차의 반폭: PERFECT 20 / GREAT 50 / GOOD 100 / BAD 150 ms (CP2 임시값) | 판정 범위 | `Windows::CP2` |
| **판정 오차** | 누른 청취 곡 시간 − 노트 시간 (+면 늦음) | 빠름/늦음 | `err_ns` |
| **MISS 확정** | watermark(또는 누름 시각)가 노트의 늦은 창 끝을 지나야 MISS로 정한다 | 놓침 | `Lane::advance` |
| **노트 고르기** | 아직 판정하지 않은 노트 중 가장 이른 것이 창 안에 있으면 그것 (CP3에서 다시 정함) | — | `Lane::press` |
| **무효** | 재동기화(Resyncing) 중의 판정·MISS를 점수·콤보에 넣지 않음 (CP2 결정, 기록은 kind 7) | 렉 직후 억울한 BAD 방지 | `--resync-judge` |
| **순수 판정** | 같은 입력 순서면 언제 어느 스레드에서 해도 같은 결과가 나오는 판정 | — | `rcore::judge` |
| **리플레이** | 기록된 입력(청취 곡 시간)만으로 판정을 다시 해 실행 중 판정과 맞대기 | 같은 플레이를 다시 재생 | `replay`, kind 8 |

## 5. 렉 감지와 상태

| 용어 | 뜻 | 게임으로 치면 | 어디에 |
|---|---|---|---|
| **고장 주입** | 일부러 스레드를 재워 렉을 만드는 것 (오디오·화면·판정·입력) | 렉 시험 | `--faults kind@초:ms`, F1~F4 |
| **맥박** | 각 스레드가 "나 살아 있다"고 남기는 마지막 QPC | — | `Heartbeats` |
| **감시 스레드** | 1 ms마다 맥박과 오디오 상태를 보고 렉 사건을 기록 | 렉 감지기 | `monitor.rs` |
| **렉 사건** | 오디오 정지(30 ms 넘게) · 언더런 · 시계 점프 · 화면 정지(50) · 판정 정지(20) · 입력 정지(20) · 상태 변화 · 재동기화 완료 | — | `lag_events.csv` |
| **상태 머신** | Running(정상) / Suspect(오디오·입력·판정 경로가 멈춘 동안) / Resyncing(시계가 새로 잡힌 뒤 200 ms 안정될 때까지) | 게임이 스스로 아는 "지금 정상인가" | `MonitorShared.state` |
| **재동기화 완료 총 밀림** | 밀리기 전 시계 직선과 다시 안정된 직선의 차이 = 음악이 실제로 밀린 양 | — | 사건 `ResyncDone` |

## 6. 프로필 (구동 방식)

| 용어 | 뜻 |
|---|---|
| **우리 방식** (`ours`) | 오디오 콜백이 곡을 직접 섞고, 판정은 입력 도장을 장치 시계로 곡 시간에 바꿔 별도 스레드에서. 화면은 다음 vblank에 들릴 곡 시간을 그린다 |
| **프레임 구동** | 화면 프레임마다 시계를 읽고, 지난 자동재생을 NOW로 울리고, 그 프레임 시각으로 판정하는 방식 (아래 셋) |
| **IIDX 개량형** (`iidx`) | 틱 = vblank (프레임당 최대 1틱). 2프레임마다 오디오와 비교해 17 ms 넘게 늦으면 틱 하나 더(1.5배속), 34 ms 넘게 앞서면 하나 쉼(0.5배속) |
| **slew / 데드밴드** | 시계를 조금씩 빠르게·느리게 해서 따라잡는 것 / 그 사이 손대지 않는 범위 (IIDX 개량형 −17~+34 ms) |
| **DJMAX식** (`djmax`) | 프레임 사이 경과 시간을 더하되 한 번에 최대 0.333초(Unity maximumDeltaTime), 판정은 200 Hz 고정 스텝 |
| **BMS식** (`bms`) | 시작 후 흐른 벽시계 시간 그대로. 입력은 1 kHz 키 상태 폴링, 재트리거 끊기 |

## 8. 측정과 지표

| 지표 | 뜻 | 게임으로 치면 |
|---|---|---|
| **M1 발음 오차** | 자동재생이 실제로 놓인 프레임 − 정답 프레임 | 배경음이 박자에서 벗어난 정도 |
| **M2 판정 시각 오차** | 프로필이 매긴 오차 − 실제로 누른 순간의 오차 | 정확히 쳤는데 판정이 틀리게 나온 정도 |
| **M3 복구 시간** | 차트↔오디오 어긋남이 10 ms 안으로 돌아와 머물 때까지 | 렉 뒤 다시 맞기까지 |
| **M4 화면 튐** | 프레임 사이 차트 이동 − 실제 흐른 시간 | 노트가 순간이동한 양 |
| **M5 장기 드리프트** | 긴 곡 끝에서 오디오 시계 − 엔진 시계 (CP2에선 재지 않음) | 곡이 길수록 밀리는 정도 |
| **M6 원곡 재현도** | 엔진 출력과 원작 미리듣기의 상관 (CP2에선 재지 않음) | — |
| **M7 판정 결정성** | 고장 없을 때와 등급이 달라진 노트 수 | 렉이 점수를 바꾼 정도 |
| **M8 입력 → 키음** | 누른 순간 → 그 키음이 장치에서 나간 순간 | 버튼 소리 지연 |
| **어긋남** | 화면(차트) 곡 시간 − 들리는 곡 시간 (+면 차트가 앞섬) | 화면과 음악이 안 맞는 양 |
| **자동 플레이어 (봇)** | 노트가 들리는 순간에 OS 입력(F24)을 넣는 측정용 플레이어. 장치 시계를 끝까지 다시 읽어 음악을 따라 친다 | 기계 손 |
| **사람 흉내 봇** | 시계 점프를 N ms 뒤에야 알아채는 봇 (`--bot-adapt-ms`) | 렉 직후 옛 박자로 치는 사람 |
| **고장 구간** | 고장마다 그 뒤 창(3초·10초)의 지표 묶음 | — |
