# Checkpoint 2 — 렉에도 키음과 반주가 맞는 게임

> 상태: **완료 (2026-10-15, 2차)** — 답: 예. 우리 방식은 세 경로 · 고장 다섯 모두에서 PERFECT 키음 vs 반주 ±1.3 ms, 세 게임식은 최대 ±1초 ([results/2-5_v2.md](results/2-5_v2.md)). 단계별 진행은 `REPORT.md`, 데모는 `DEMO.md`, 용어는 `GLOSSARY.md`.
> 1차 시도(브랜치 `cp2-attempt1`)는 "현재 = 출력 위치"로 잡아 PERFECT 키음이 반주보다 출력 지연만큼 늦었다. 그래서 되돌렸고, CP1-4에서 기록 시계를 세운 뒤 다시 시작한다.
> 근거: [../design/기록 시계 설계.md](../design/기록%20시계%20설계.md), CP1-4 실측([../cp1/REPORT.md](../cp1/REPORT.md)), CP0 분석.

## CP2가 답할 질문

> 우리 게임은 앞선 세 게임(IIDX·DJMAX·BMS)과 달리, 각종 오류(오디오·화면·판정·입력 정지)가 나도 **PERFECT 판정을 받은 키음이 반주와 같은 샘플에 놓이는가?**

- 기본 지표: **PERFECT 키음 vs 반주** (루프백 녹음에서, 샘플 단위). 우리 게임은 0이어야 한다. 정지 구간에 누른 키음처럼 물리적으로 낼 수 없는 소리는 손실로 따로 센다.
- 세 게임식 프로필은 같은 지표로 잰다: 그 게임이 PERFECT라고 판정한 누름의 키음 vs 반주(이미 울리던 긴 반주 포함). 오류에 얼마나 취약한지 보여 주는 대조군이자 데모.

## 원칙

- **시계는 하나: 기록 시계 C = 장치 시계 + D** (CP1-4 계약). 채보·판정·화면·음악 예약·키음 예약이 모두 C를 쓴다. 오디오 정지는 콘텐츠를 건너뛰어 C를 끊지 않는다.
- **오디오 경로는 선택식**: WASAPI 공유, WASAPI 배타(5 ms 주기), ASIO. D는 시작할 때 경로별로 재서 정하고 플레이 중 고정한다(측정 최대 + 2 ms).
- **하드코딩은 게임 디자인 쪽만**: 건반 하나, 판정 창, 화면 모양. 코어(정규 시간, 오디오, 입력, 판정, 렉 감지, 기록, 고장 주입)는 진짜로 만든다.

## 범위

| 부품 | 하는 일 | 1차 시도에서 |
|---|---|---|
| 실행 데이터 (`.rtc`) | 정규 시간 ns, 소비자별 정렬 배열, PCM 뱅크, 보이스 예산, 해시 | 재사용 |
| 오프라인 믹서 | 정답 렌더, 블록 크기와 무관하게 비트 단위로 같음 | 재사용 |
| 오디오 경로 | 공유·배타·ASIO, 경로별 D 자동 측정, 오디오 정지 때 건너뛰기 | 새로 (CP1-4 부품 이식) |
| 입력·판정·키음 | Raw Input 입력 시각 → C, 순수 판정, 키음은 C(누른 시각)에 예약 | 시계 정의만 바꿔 재사용 |
| 화면 | 레인 1개, 노트, 판정선, HUD. C를 그린다 | 재사용 |
| 렉 감지 | 심장박동 감시, 상태 머신, 기록 | 수정 (재동기화 점프가 없어짐) |
| 비교 프로필 | IIDX 개량형 · DJMAX식 · BMS식 (프레임 구동) | 재사용, 지표만 교체 |
| 측정 | 자동 플레이어(PERFECT 순간에 SendInput), 루프백 분석, 리플레이 | 수정 |

시험 콘텐츠: 합성 곡(120 BPM, 4분음표 256개, 9초 패드), DJMAX 곡 2개(BlythE, Negative Nature, 원본 복호화), BMS 출신 표본 Unshakable(6K U_E 팩). 비공개, `content/`는 git 제외.
