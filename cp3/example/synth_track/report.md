# 합성 예시 Track 보고서 (2026-10-17)

Track 형식 명세 v1(`../../Track_형식.md`)의 **받는 쪽 테스트벤치** (README 7장 3-0). 소리는 `../make_audio.py`로 직접 합성했고, `../check_example.py`가 명세 2·3장대로 읽어 검산한다(컴파일러가 아니라 명세의 검산기).

## 검산 결과 (`python -X utf8 cp3/example/check_example.py`, 명세 v1.2)
- 문제 0, 기대값 11개 모두 일치(다르면 종료 코드 1).
- 소리 10개: Ogg Vorbis 3(44.1k·48k), FLAC 4(16·24비트, 44.1k·**30,697 Hz**), MS-ADPCM 3(22.05k). `piano_c` = `piano_c_alt`(PCM 같음, ID 다름) → 데이터 한 번, ID는 따로. 소리 해시는 명세 3-5의 바이트열(`"SND1"` ‖ rate ‖ channels ‖ frames ‖ PCM)로 계산(검산기는 BLAKE3 대신 blake2b).
- 차분 4: `8b-a`(tick, 8B, 원점), `7k-b`(박·마디:박, 7+1, shift −500, 정지 + 명시 스크롤, 변형 r1·r2와 AND 조건, 지뢰 damage, 빈 레인 소리), `7k-c`(ms, 7+1, IIDX식 정수 반올림 스크롤, 이벤트 이득, cut 재발음), `7k-b-x1.25`(배속 변형 5/4, shift 기본값 −400).
- 기대값: tick 1728 = 13000/3 ms = 4,333,333,333 ns / 배속 변형 shift 기본값 −400 ms / 반주 stem이 4차분 모두 Track 0에서 하나 / 음수 Track 시각 2곳 / 8b-a choke 1회 / 7k-c cut 1회(같은 PCM 다른 ID는 안 끊음) / 7k-b STOP 구간이 명시 스크롤에 들어감 / 정지 뒤 노트 6.5초 / 아르페지오 offset 125 ms / 변형 조합 4개.
- 음악 레이어 44개, 둘 이상 차분이 공유 9개(공유는 차분 ID 집합으로 셈, 최종 이득 = 소리 이득 × 이벤트 이득으로 구분).
- 반례 시험(검산기가 실패로 잡는지): 알 수 없는 키, lane_sound의 없는 소리·레인, 음수 이득, 배속 변형에 layout, 음수 배속, 정답 시각 틀림, ns 반올림 뒤 겹침, 중복 소리 ID — 9건 모두 종료 코드 1.
- `make_audio.py`를 두 번 다시 돌려 저장된 오디오와 바이트까지 같음. 도구 버전·파일·PCM 해시는 `audio/MANIFEST.txt`.

## 명세에서 막힌 곳 → 명세 v1.1에 반영
| # | 막힌 곳 | 고친 것 |
|---|---|---|
| G1 | `[scroll]`의 `speed` 단위가 모호("기준 박/박") | **박/분**(bpm과 같은 단위). 실행 형식은 박/초로 바꿔 담음 |
| G2 | 스크롤 점마다 `pos`를 손으로 계산해야 함 | `pos` 선택: 없으면 앞 점에서 이어지는 위치. 순간 이동일 때만 적음 |
| G3 | 같은 레인·같은 시각의 변형 대안 노트(when = r1=a / r1=b)가 "겹침" 규칙에 걸림 | 겹침 검사는 **변형 선택 조합마다** |
| G4 | 지뢰를 밟으면 무엇이 일어나는지 없음 | `damage`(게이지 %, 선택) 추가, 기본값은 규칙 ⚑ (CP3 기본: BAD와 같은 감소) |
| G5 | `lane_sound`가 언제까지 유효한지 없음 | 그 레인의 다음 노트(판정 후 그 노트 소리로 바뀜) 또는 다음 `lane_sound`까지 |
| G6 | 배속 변형 차분이 무엇을 물려받는지 없음 | base의 레이아웃·규칙·시간 지도·스크롤·이벤트·노트·변형을 물려받음. 적는 것은 id·name·level·time_scale, 선택으로 shift(기본 base.shift ÷ time_scale)·reference_scroll(기본 base × time_scale) |
| G7 | 음악 레이어에서 같은 PCM이지만 `start`·`gain`이 다른 소리(piano_c ↔ piano_c_alt)가 같은 이벤트로 셈 | 레이어 이벤트 = (Track 시각, 소리 해시, start, gain) |
| G8 | `start` 뜻이 모호 | "앞에서 버릴 샘플 수(원본 레이트)" |
| G9 | 정지 위치와 같은 위치의 이벤트가 정지 전인지 후인지 없음 | **정지 전**(BMS 동작). 정지 뒤 첫 이벤트는 정지가 끝난 시각 |
| G10 | beat·tick 단위의 tempo가 0에서 시작해야 하는지 없음 | 필수 |
| G11 | `when`에 조건 여럿·중첩 #IF | v1은 `id=선택` 하나만. 중첩은 ⚑ (2차 연구: #RANDOM 0.5%, 중첩 실태 미조사) |
