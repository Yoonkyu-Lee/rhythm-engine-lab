# Windows PC 리듬게임 타이밍 설계

## 1. 목표와 보장 범위

우선순위는 다음과 같다.

1. 실제 청취 위치와 다른 시각을 정상으로 취급할 가능성을 낮춘다.
2. 대응 관계가 깨지면 감지하고, 검증 가능한 상태로 재동기화한다.
3. 입력→발음 지연과 지터를 줄인다.
4. 구현·CPU·유지보수 비용을 제한한다.

소프트웨어가 직접 관측하는 것은 장치와 OS의 보고값이다. 귀 도달 시각은 여기에 외부 교정값을 적용한 **추정**이다. 관측되지 않는 경로 변화까지 자동 검출한다고 주장하지 않는다.

비목표:

- 임의의 Windows PC에서 100 µs 종단 정확도 보장.
- 유한한 최악 스케줄링 지연 보장.
- 이미 누락된 음이나 접점 이벤트의 사후 복원.
- Bluetooth를 유선 저지연 장치와 같은 등급으로 취급.
- 프레임 정지를 부드러운 노트 추격으로 감추기.

## 2. 시간축과 커서

| 이름 | 정의 | 용도 |
|---|---|---|
| QPC 시간 `q` | `QueryPerformanceCounter`와 조회한 주파수로 해석하는 호스트 시간 | 입력 수신·장치 관측·진단의 공통 시간축 |
| 정규 곡 시간 `c` | 장치와 독립적인 정수 시간. 초기 구현은 i64 ns | 채보·판정·리플레이 |
| 스트림 프레임 `f` | 한 오디오 epoch 안의 출력 프레임 좌표 | 버퍼 배치·장치 위치 대응 |
| 제출 커서 `W` | 백엔드에 성공적으로 넘긴 구간의 다음 프레임 | 제출 이력. 재생 완료를 의미하지 않음 |
| 재생 커서 `R(q)` | 시각 `q`에서 백엔드 기준점을 통과하는 프레임의 추정 | 현재 출력 위치 |
| 콘텐츠 대응 `C(f)` | 출력 프레임에 배치한 곡 위치. 무음·불명 구간도 표현 | 재생 위치를 곡 시간으로 변환 |
| 청취 곡 시간 `H(q)` | 시각 `q`에 귀에 도달한다고 추정되는 프레임의 `C(f)` | 판정·화면 예측 |
| 쓰기 가능 구간 | 현재 안전하게 채울 수 있는 프레임 범위 | 키음 예약·자동재생 믹싱 |

`W`, `R`, `C`는 합치지 않는다. 정상 연속 재생에서는 단순한 대응이지만, 선행 버퍼링·무음·재시작 뒤에는 달라진다.

장치가 명목 48 kHz라는 사실과 QPC 기준 실제 진행률은 구분한다. 진행률 추정으로 채보 자체를 다시 컴파일하지 않는다.

채보 시각은 유리수로 누적한 뒤 정규 시간으로 한 번 반올림한다. 오디오 프레임으로 변환할 때 별도의 반올림이 발생한다. 두 오차를 “0”이라고 부르지 않는다.

## 3. 오디오 백엔드 시간 계약

```rust
struct Epoch(u64);
struct QpcTicks(i64);
struct StreamFrame(i64);
struct SongNs(i64);

enum ClockState {
    Acquiring,
    Tracking,
    Stale,
    Discontinuous,
}

enum Uncertainty {
    Unknown,
    // 명시한 운용 조건에서 검증한 경험적 오차 범위.
    // 하드 실시간 상한이 아니다.
    Empirical { ns: u64, profile_id: u64 },
}

struct PresentationModel {
    epoch: Epoch,
    frame0: StreamFrame,
    qpc0: QpcTicks,
    qpc_ticks_per_frame: f64,
    observed_at: QpcTicks,
    valid_until: QpcTicks,
    state: ClockState,
    uncertainty: Uncertainty,
}

struct RenderBlock {
    epoch: Epoch,
    frames: Range<StreamFrame>,
    deadline_estimate: Option<QpcTicks>,
    // 실제 PCM 버퍼는 콜백 수명에 한정된 별도 참조.
}

struct ContentSegment {
    epoch: Epoch,
    frames: Range<StreamFrame>,
    content: ContentMapping, // Song / Silence / Unknown
}
```

`PresentationModel`은 **프레임이 백엔드가 정의한 출력 기준점을 통과할 QPC**를 반환한다. 기준점의 의미를 백엔드 문서에 고정한다.

귀 도달 모델은 다음과 같다.

```text
ear_qpc(frame) = presentation_qpc(frame) + residual_path_delay
```

`residual_path_delay`는 API 기준점에 이미 포함되지 않은 경로만 보정한다. 보고된 전체 지연을 무조건 다시 더하거나 빼지 않는다.

백엔드 규칙:

- WASAPI 위치는 `IAudioClock::GetFrequency`로 해석한다.
- WASAPI의 상관 QPC 값은 100 ns 단위임을 변환 계층에서 처리한다.
- ASIO는 가능하면 `bufferSwitchTimeInfo`를 사용한다.
- ASIO 블록 시작·버퍼 인덱스·출력 지연을 구분한다.
- ASIO 시스템 시각의 단위와 QPC 대응을 검증한다.
- 직접 센 프레임은 제출·블록 순서 검증에 쓴다.
- 공유/배타 모드의 버퍼 계약을 동일하다고 가정하지 않는다.
- 백엔드가 위치 품질을 제공하지 못하면 `Unknown`으로 공개한다.

API 근거: [WASAPI 위치](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition), [ASIO SDK](https://raw.githubusercontent.com/audiosdk/asio/master/common/asio.h).

## 4. 시계 추정과 유효성

상관된 장치 위치·시각 관측으로 프레임→QPC 직선을 추정한다.

- 위상과 진행률을 별도로 추적한다.
- 큰 절대 카운터 대신 기준점과의 차이로 계산한다.
- 진행률은 느리게 갱신하고 관측 이상치는 분리한다.
- 장치 보고 품질·관측 나이·불연속 신호를 함께 평가한다.
- 콜백 진입 QPC는 주로 깨움 지연 측정에 사용한다.
- 콜백 시각만 가능한 장치는 낮은 신뢰 등급으로 분류한다.
- 작은 회귀 잔차를 물리 정확도의 증거로 사용하지 않는다.

초기 정책:

- 새 epoch에서 최소 100 ms, 8개 이상의 일관된 관측을 확보한 뒤 시작을 허용한다.
- 명목 진행률로 시작하되, 진행률 적응은 최소 2초의 유효 관측 후 활성화한다.
- 관측이 `max(3 × 서비스 주기, 10 ms)` 이상 오래되면 `Stale`.
- 정상 재생 중 설명되지 않는 2 ms 이상의 모델 점프는 재검증 대상으로 삼는다.
- 작은 잔차는 관측 품질에 따라 처리한다. 임계값은 백엔드 측정 결과로 조정한다.

이 숫자는 초기 운영 정책이다. 정확도 보장이 아니다.

과거 입력을 최신 직선으로 계속 재해석하지 않는다. 입력을 처리할 때 사용한 epoch·모델 버전·정규 곡 시각을 기록한다. 나중에 모델 오류가 드러나면 해당 구간을 무효 표시한다.

## 5. 스레드와 소유권

| 실행 경로 | 소유 상태 | 제한 |
|---|---|---|
| 오디오 콜백 | 보이스, 믹서, 자동재생 커서, 예약 키음 | 할당·해제·블로킹·파일 작업 금지 |
| 입력/판정 스레드 | 입력 순서, 레인 상태, 판정, watermark | 렌더·오디오 완료를 기다리지 않음 |
| 렌더 스레드 | GPU 자원, 표시 예측 | 최신 스냅샷만 소비 |
| 제어/로딩 경로 | 디코딩, 장치 재구성, 로그 저장 | 실시간 경로가 기다리지 않게 함 |

판정은 작으므로 초기 구현에서는 입력과 같은 스레드에 둔다. 키음 선택과 판정 대상 선택을 서로 다른 스레드에서 중복 구현하지 않는다.

입력/판정 스레드가 레인 규칙에 따라 키음을 선택하고, 즉시 오디오 SPSC에 요청한다. MISS 확정처럼 유예가 필요한 처리는 뒤에서 수행한다.

통신 규칙:

- 이벤트 큐와 최신 상태 스냅샷을 구분한다.
- 큐는 고정 용량이며 생산자가 소비자 인덱스를 임의로 변경하지 않는다.
- 입력 overflow는 이벤트 손실로 기록하고 버튼 상태를 재동기화한다.
- 해제·큰 객체 파괴는 제어 경로로 보낸다.
- 시계 스냅샷 읽기는 재시도 횟수를 제한한다.
- 다중 필드 일관성과 Rust 메모리 모델을 만족하는 검증된 전달 수단을 사용한다.
- lock-free를 무제한 대기 부재와 동일시하지 않는다.

PCM·스택·주요 코드 경로를 재생 전에 접근하고 워밍업한다. 필요한 작업 집합의 상주를 요청할 수 있지만 성공 여부를 검사하며 실시간 보장으로 취급하지 않는다. DSP는 denormal 처리 정책을 고정한다.

## 6. 입력 시각과 판정 watermark

```rust
enum InputTimeSource {
    HostReceipt,
    DeviceMapped { clock_epoch: u64 },
}

struct InputEvent {
    sequence: u64,
    device: DeviceId,
    control: ControlId,
    edge: Edge,
    qpc: QpcTicks,
    source: InputTimeSource,
    uncertainty: Uncertainty,
}

struct InputWatermark {
    // 이 시각 이전으로 배치할 수 있는 이벤트를 모두 게시했다는
    // 생산자 계약. 물리 접점 전체를 관측했다는 뜻은 아니다.
    qpc: QpcTicks,
    sequence: u64,
}
```

일반 Raw Input:

- 가능한 이른 수신 지점에서 QPC를 기록한다.
- 배치 내 이벤트 순서는 보존한다.
- OS가 제공하지 않은 과거 접점 시각을 만들어내지 않는다.
- 수신 지연에는 스캔·디바운스·USB·OS 지연이 남는다.
- 입력 간격 히스토그램을 USB 폴링 주기라고 표시하지 않는다.

장치 타임스탬프가 있는 입력:

- 장치 클럭→QPC 대응을 별도로 추정한다.
- wrap·reset·역순·누락을 검사한다.
- watermark는 장치 시간과 전송 계약까지 반영해야 한다.
- 무제한 지연을 허용하면서 유한 시간 안에 MISS를 확정할 수는 없다.

판정:

```text
input_song_time = H(input_qpc)
finalize MISS only when:
    input watermark > note late-window endpoint
```

여러 입력원이 있으면 유효한 watermark의 최솟값을 사용한다. 멈춘 입력원은 무한히 전체 판정을 막게 두지 않고, 연결 상실 또는 입력 불확실 상태로 전환한다.

watermark 이전 시각의 이벤트가 뒤늦게 오면 계약 위반이다. 조용히 점수를 바꾸지 않는다. 해당 구간을 무효 처리한다. 연습 모드의 제한된 롤백은 나중에 선택적으로 추가한다.

판정 창, 동시각 이벤트 순서, 레인 배치, 난수 시드, 엔진 버전을 리플레이에 포함한다. 리플레이 재현 가능성과 입력의 물리 정확성은 별개다.

## 7. 자동재생과 키음

### 자동재생

오디오 콜백이 출력 프레임 구간에 해당하는 콘텐츠를 직접 믹싱한다. 렌더·일반 로직의 진행을 기다리지 않는다.

보이스 용량 초과 시 정책을 고정한다. 반주를 무조건 가장 오래된 보이스로 취급해 끄지 않는다. 우선순위와 짧은 감쇠를 적용하고 초과를 기록한다.

### 플레이어 키음

기본은 **최소 지연 모드**다. 요청을 받은 뒤 가장 이른 안전한 출력 프레임에 배치한다. 이 모드에는 서비스 주기와 전달 지연에 따른 지터가 남는다.

선택적으로 **일정한 예약 지연 모드**를 제공한다.

```text
target_ear_qpc = input_qpc + chosen_delay
target_frame  = inverse_ear_model(target_ear_qpc)
```

`chosen_delay`는 실제 요청 경로의 높은 분위수와 출력 선행량을 보고 정한다. 유한한 최악 지연으로 설명하지 않는다. 플레이 도중 조용히 변경하지 않는다.

오디오 콜백의 처리:

| 요청 상태 | 처리 |
|---|---|
| 목표가 현재 쓰기 가능 구간 안 | 해당 프레임 오프셋에 믹싱 |
| 목표가 미래 | 고정 용량 예약 큐에 보관 |
| 목표가 이미 지남 | 가장 이른 안전한 프레임에 발음하고 지각량 기록 |
| 목표보다 20 ms 이상 늦음 | 초기 정책상 폐기하고 실패 기록 |
| 다른 epoch의 요청 | 폐기 |

20 ms는 제품 정책이며 검증 후 조정한다. 늦은 요청으로 과거 판정 시각을 옮기지 않는다.

고정 지연 모드가 제거하는 것은 관측된 입력 시각 이후의 일부 예약 지터다. 접점→수신 지터는 제거하지 못한다.

## 8. 상태 머신과 콘텐츠 재동기화

```text
Stopped
  → Priming
  → Acquiring
  → Running
  → Suspect
  → Resyncing
  → Priming

Running → Paused → Priming
어느 상태든 장치 오류 → Unavailable → Priming
```

- `Priming`: 버퍼·보이스·콘텐츠 대응 준비.
- `Acquiring`: 장치 위치·시각·버퍼 관계 확인.
- `Running`: 유효한 시간 계약으로 판정·발음.
- `Suspect`: 새로운 확정 판정을 보류하고 불확실 구간 기록.
- `Resyncing`: 정지·플러시·새 epoch·콘텐츠 재배치.
- `Paused`: 곡 시간 정지. QPC 외삽도 정지.
- `Unavailable`: 장치가 다시 준비될 때까지 대기.

복구 정책은 두 가지다.

**재생 위치와 콘텐츠 대응이 확실한 경우**

현재 위치로 전진한다. 지나간 자동재생 이벤트를 몰아서 발음하지 않는다. 해당 시각에 살아 있어야 할 장음은 PCM 오프셋에서 복원하고 짧게 페이드인한다.

**대응이 불확실한 경우**

정지·플러시 후 새 epoch를 만든다. 연습 모드는 명시된 체크포인트에서 판정·보이스 상태를 함께 복원한다. 연속 정확성이 필요한 점수 기록은 중단 또는 무효 처리한다.

점수 상태는 유지한 채 음악만 과거로 돌리지 않는다. 이미 들리지 않은 소리는 복구됐다고 기록하지 않는다.

## 9. 화면 정책

노트와 판정선은 **예상 광학 표시 시각에서의 최선 청취 곡 시간**을 사용한다.

```text
estimated_photon_qpc =
    predicted_display_time + calibrated_line_offset

note_position = chart_position(H(estimated_photon_qpc))
```

- 렌더 시작을 프레임 대기 해제 뒤로 늦추고, 가능한 늦게 시계를 읽는다.
- 노트 진행을 0.5~1.5배로 조절해 과거 오차를 끌고 가지 않는다.
- 큰 오차나 프레임 누락 뒤에는 현재 추정 위치로 즉시 복귀한다.
- smoothing은 배경·장식에만 적용한다.
- present 통계는 광학 센서가 아니다.
- present ID, 모드 변경, 통계 disjoint를 처리한다.
- VRR 범위·반복 표시·출력 모니터 변경 시 표시 모델을 재검증한다.
- 사용자의 화면 보정은 오디오·입력 보정과 분리한다.

## 10. 실패 처리

| 실패 | 감지 | 행동 | 복구 가능 / 불가능 |
|---|---|---|---|
| 렌더 정지 | 프레임·present 간격 | 다음 프레임에 현재 상태 표시 | 현재 표시 복구 / 놓친 화면 복구 불가 |
| 입력/판정 지연 | 수신·처리 시각, watermark 지연 | 보존된 이벤트 순서대로 처리 | 보존된 타임스탬프 판정 / 미관측 접점 시각 복구 불가 |
| 입력 큐 손실 | sequence gap·overflow | 상태 재동기화, 구간 무효 | 버튼 현재 상태 / 유실된 edge 복구 불가 |
| 키음 지각 | 목표 프레임과 쓰기 가능 구간 비교 | 즉시 발음 또는 폐기 | 향후 예약 / 원래 발음 시각 복구 불가 |
| 오디오 마감 실패 | 진입 지연·완료 여유·드라이버 통지 | 콘텐츠 대응 검증, 필요 시 재동기화 | 향후 재생 / 누락된 음 복구 불가 |
| 위치 보고 정지·불연속 | 관측 나이·위치·잔차·알림 | 외삽 중단, 새 epoch | 새 대응 / 불확실 구간의 사실 확정 불가 |
| 장치·주기·포맷 변경 | 백엔드 이벤트·오류 | 정지·재구성·교정 유효성 재확인 | 새 스트림 / 무중단 연속성 보장 불가 |
| 절전·휴면 복귀 | 전원 알림·긴 관측 공백 | 기존 모델 폐기, 재획득 | 재개 / 공백 중 연속성 복구 불가 |
| 스트리밍 고갈 | 준비된 PCM 부족 | 명시적 무음·실패 기록, 반복 시 정지 | 이후 콘텐츠 / 누락 콘텐츠 복구 불가 |
| 외부 DSP·패널 경로 변경 | 내부에서 감지 못할 수도 있음 | 교정 무효화 또는 외부 재측정 | 재교정 / 자동 탐지 보장 불가 |

언더런 검출도 완전하다고 가정하지 않는다. 장치가 무음이나 이전 버퍼를 출력하면서 카운터는 정상 진행할 수 있다.

## 11. 측정과 승인 기준

### 소프트웨어 측정

사전 할당된 스레드별 이진 로그에 다음을 남긴다.

- 콜백 진입 지연, 실행 시간, 추정 마감 여유.
- 제출 구간·장치 위치·epoch·콘텐츠 대응.
- 모델 잔차, 관측 나이, 불확실 상태.
- 입력 수신·처리·키음 목표·실제 배치 프레임.
- watermark, queue overflow, late request.
- present ID, 표시 추정과 실제 통계 차이.

로그 켜짐/꺼짐의 마감 실패 분포를 비교한다. 평균뿐 아니라 편향, p99, p99.9, 관측 최대값, 실패율을 보고한다.

### 물리 측정

- 전기 접점 기준 신호, 마이크, 광센서를 가능한 한 같은 ADC로 동시 기록한다.
- 광센서는 실제 판정선 위치에 둔다.
- 접점 신호는 레벨·바이어스·절연을 맞춘 측정 회로를 사용한다.
- 출력→입력 루프백은 왕복 경로 측정이다. 순수 출력 지연과 동일시하지 않는다.
- 귀 위치 마이크로 스피커·공기 경로를 포함한다.
- 신호 시작 검출 기준과 필터 지연을 기록한다.
- 장치·포맷·주기·DSP·화면 모드별로 반복 측정한다.

### 초기 승인 문턱

다음은 **검증한 구성의 승인 기준**이다. 모든 PC에 대한 보장이 아니다.

| 대상 | 초기 기준 |
|---|---|
| 채보·판정 결정성 | 같은 정규 이벤트와 설정에서 완전히 같은 결과 |
| 정상 연속 믹싱 | 예정 프레임 배치 오차 최대 1프레임 |
| 유선 오디오 시간 모델 | 교정 후 물리 측정 절대 오차 p99.9 ≤ 0.5 ms, 관측 최대 ≤ 2 ms |
| 일정 지연 키음 모드 | 유효 타임스탬프·마감 충족 요청에서 목표 도달 오차 p99.9 ≤ 0.5 ms |
| 100 µs 목표 | 별도 실험 등급. 측정계 불확실성부터 검증하며 기본 승인에 사용하지 않음 |
| 판정 지연 주입 | 입력 시각 보존·큐 무손실 조건에서 500 ms 처리 정지 후 결과 동일 |
| 장시간 안정성 | 구성별 2시간 부하 시험에서 언더런·입력 손실 0. 향후 무발생 보장으로 해석하지 않음 |
| 시계 관측 만료 | 유효기간이 지난 모델로 새 판정 확정 0건 |
| epoch 변경 | 이전 epoch 키음 발음 0건 |
| 불연속 복귀 | 조건이 회복된 뒤 2초 안에 Running 또는 명시적 실패 상태 |
| 고정 주사율 표시 | 판정선 광학 예측 오차 p99 ≤ 1 ms를 목표. 실패 구성은 측정된 오차 등급 표시 |

입력 접점→수신 지연과 전체 접점→음압 지연은 따로 보고한다. 일반 키보드에 0.5 ms 입력 정확도를 요구하거나 암시하지 않는다.

부하 시험에는 CPU·GPU 경쟁, 메모리 압박, USB 활동, 드라이버 지연, 렌더 정지, 오디오 마감 실패, 장치 재시작, 절전 복귀를 포함한다.

## 12. 의도적으로 만들지 않는 것

- 스레드마다 PLL을 두는 CDC 모사.
- 자체 제출 카운터를 물리 시계로 승격하는 구조.
- 전역 busy-spin이나 무조건적인 최고 우선순위.
- 측정 없이 적용하는 코어 고정·타이머 해상도 변경.
- 초기부터의 128비트 원자 연산·자작 seqlock.
- 노트 오차를 숨기는 긴 smoothing.
- 초기부터의 자체 드라이버·직접 DX12/Vulkan 백엔드.
- 일반 입력 히스토그램으로 USB 폴링·접점 정확도를 추정하는 UI.
- 탭 평균을 객관적 하드웨어 교정이라고 부르는 기능.
- 수백 µs 관측 오류를 남긴 채 수십 ns 최적화에 집중하는 작업.

## 13. 구현 순서

1. 정규 채보 시간·판정·리플레이 코어. 동시각 순서와 버전 규칙 확정.
2. 오프라인 믹서와 콘텐츠 대응. 프레임 배치·장음 복원·용량 초과 정책 검증.
3. WASAPI 공유 이벤트 경로 하나로 시간 계약 구현. 지원 시 저지연 주기 사용.
4. 아날로그 출력 측정으로 위치·지연 기준점 검증. 그 전에는 정확성 등급을 부여하지 않음.
5. 입력/판정 스레드, watermark, 최소 지연 키음, late 정책 구현.
6. 최소 렌더와 present 기록. 광센서로 표시 예측 검증.
7. 마감 실패·장치 변경·절전·overflow 주입 시험과 상태 머신 완성.
8. WASAPI 배타·ASIO 어댑터 추가. 동일 계약 시험을 각각 통과시킴.
9. 일정 지연 키음 모드와 장치 타임스탬프 지원 추가.
10. 측정에서 드러난 병목만 최적화.

완료 기준은 “시계가 계속 증가한다”가 아니다. **정상 구간의 물리 오차가 측정됐고, 불확실 구간을 정상으로 처리하지 않으며, 실패 뒤 새 대응을 검증하고 재개하는 것**이다.
