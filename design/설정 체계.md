# 설정 체계 — 무엇을 어디에 두는가

> 작성일 2026-10-16. 근거: `../cp0/Qwilight_settings.md`(Qwilight 설정 277개 전수 목록), CP2 결정(`../cp2/README.md`의 "CP3로 넘기는 것").
> 원칙: Qwilight의 **설정 원리**(BMS 곡을 플레이어가 해석하는 방식)는 따르지 않는다. **자유도**(무엇을 바꿀 수 있는가)는 빠짐없이 가져와 우리 엔진의 말로 다시 정의한다.
> 표기: **CP3** = 칠 수 있는 게임(로직·데이터, 조작 가능한 설정창 포함), **CP4** = 보이는 게임(화면·스킨·연출).

---

## 0. 분류 기준

Qwilight는 설정을 **기능 영역**(플레이 / 입력 / 그래픽 / 오디오 / 일반)으로 나눈다. 그래서 같은 성격의 설정이 여러 탭에 흩어진다 — 판정 루프 주기는 "일반 → 성능", 오디오 오프셋은 "오디오", 노트 표시 오프셋은 "비주얼"에 있다.

우리는 **"그 설정이 무엇의 진실을 바꾸는가"**로 나눈다. 우리 엔진의 약속(기록 시계: PERFECT 키음 = 반주)과 곡의 원칙("곡에는 곡의 진실만")에서 나오는 기준이다.

| 묶음 | 바꾸는 것 | 판단 질문 | 결과(점수·리플레이)에 |
|---|---|---|---|
| **1. 규칙** | 무엇이 맞은 것인가 | 같은 손놀림에 점수가 달라지는가? | **기록한다.** 규칙이 같은 결과끼리만 비교 |
| **2. 장비와 몸** | 내 장치·내 손의 지연과 보정 | 장치나 사람이 바뀌면 다시 맞춰야 하는가? | 기록한다 (진단용, 비교에는 안 씀) |
| **3. 소리** | 무엇이 들리는가 | 판정은 그대로인데 들리는 것만 바뀌는가? | 기록하지 않음 |
| **4. 입력** | 어떤 물리 입력이 어느 레인인가 | 키 배치·장치 해석인가? | 기록하지 않음 |
| **5. 화면** | 무엇이 보이는가 | 판정·소리는 그대로인데 보이는 것만 바뀌는가? | 기록하지 않음 |
| **6. 라이브러리** | 곡을 찾고 고르는 것 | 플레이 밖인가? | — |
| **7. 엔진 (고급)** | 구동 정책·진단 | 엔진 실험·문제 추적용인가? | 기록한다 (어떤 정책으로 돌았나) |

규칙:
- **판정을 바꾸는 설정은 1에만 둔다.** 다른 묶음의 설정은 판정을 바꾸면 안 된다 (CP2 교훈: 판정만 옮기는 오프셋이 "PERFECT = 키음이 반주 위"를 깨뜨렸다).
- **2의 오프셋은 판정과 소리를 함께 옮기거나(A) 화면만 옮긴다(B).** 판정만 옮기는 오프셋은 두지 않는다.
- **범위(scope)를 설정마다 명시한다**: 전역 / 장치별 / 키 모드별 / 곡별 / 프리셋. Qwilight는 같은 성격의 값이 곡별·장치별·스킨별로 흩어져 더해진다(오디오 오프셋 = 곡별 + 장치별). 우리는 더해지는 층을 화면에 함께 보여 준다.
- **기본은 단순하게, 고급은 숨김.** 각 묶음 안에서 "기본"과 "고급"을 나눈다.

## 1. 규칙 (CP3: 고정 기본값 / CP4: 커스텀·프리셋)

> 2026-10-17 결정: CP3는 IIDX식 판정 창·게이지 기본값 하나로 모든 원작을 친다. 아래 규칙들을 사용자가 바꾸고 프리셋으로 저장하는 시스템은 **CP4**에서 Qwilight의 자유도처럼 만든다. CP3 엔진은 규칙을 데이터로 다뤄 CP4가 코드 수정 없이 얹히게 한다.

| 설정 | Qwilight 대응 | 우리 정의 | 범위 |
|---|---|---|---|
| 판정 창 | `JudgmentModeValue`(난이도 5종) + `FavorJudgments`(6등급 × 빠름/늦음 ms) | 등급별 빠름·늦음 경계(ns). 이름 붙은 프리셋 + 사용자 지정. 곡(차분)이 기본 판정 창을 가질 수 있음 | 프리셋 |
| 게이지 | `HitPointsModeValue`(9종) + `FavorHitPoints` + `GASLevel` + `IsInfiniteMode` | 게이지 종류·증감 규칙, 자동 전환(GAS) 허용 단계, 무한 모드 | 프리셋 |
| 롱노트 규칙 | `LongNoteModeValue` | 끝 판정 유무·떼기 판정. 차분의 기본 규칙 위에 덮어쓰기 | 프리셋 |
| 빈 누름 판정 | `LowestJudgmentConditionModeValue` | 창 밖 빈 누름에 MISS(간접 미스) 여부 | 프리셋 |
| 노트 고르기 | (없음, 암묵) | 같은 레인 연타·겹친 창에서 어느 노트를 판정하나 (CP2 토론). 판정과 키음이 같은 함수를 씀 | 엔진 규칙(설정 아님, 명시만) |
| 채보 변형 | `NoteSaltModeValue`(랜덤 9종), `InputFavorModeValue`(키 수 변환 30종), `NoteModifyModeValue`(숏↔롱), `SetNoteModeValue`(노트 추가), `WipeCenterNotes`, `PutCopyNotesValueV2`, `WaveModeValue`(역방향), `AutoModeValue`(자동 턴테이블) | 로드 단계 변형 목록. **레인 모델 위에서 정의**(레인 묶음 안 섞기, 레인 수 바꾸기 등 — 키 모드가 매개변수라서 "7K 랜덤" 같은 하드코딩 없음) | 프리셋 |
| 시드 | `Salt`, `SetSalt`, `SaltAuto` | 변형 난수 시드, 고정 여부. 리플레이에 기록 | 프리셋 |
| 음악 속도 | `AudioMultiplier`, `AudioMultiplierAtone` | 곡 시계 배속(0.5~2배)과 피치 보정. 기록 시계 C 전체를 배속 — 판정 오차는 원래 속도 기준으로 환산 | 프리셋 |
| 프리셋 | `ModeComponentBundles`(8칸) | 1의 설정 묶음을 이름 붙여 저장 | 전역 |

## 2. 장비와 몸 (CP3)

| 설정 | Qwilight 대응 | 우리 정의 | 범위 |
|---|---|---|---|
| 오디오 출력 | `AudioVariety`, `AudioDataLength`, `Last*AudioValueID` | 경로(WASAPI 공유 / 배타 + 주기 / ASIO + 버퍼), 장치 선택 | 전역 |
| D | (없음) | 자동(리드인 측정 최대 + 여유) / 수동. 여유(ms) | 장치별 |
| 오프셋 A (판정·키음) | (없음 — Qwilight엔 판정 오프셋이 없다) | 판정 기준과 키음 위치를 함께 옮김. 키음 지연 = D + A. 음수는 D 여유까지 | 장치별 + 사람 |
| 오프셋 B (화면) | `UIConfigure.NoteWait`("노트 레이턴시"), `AutoNoteWait` | 노트 그리기만 옮김(모니터 지연). 곡 끝 자동 보정 선택 | 화면 장치별 |
| 보정 도구 | `AutoNoteWait`(곡 끝 평균) | 소리로 맞추기(A) · 화면으로 맞추기(B) 두 화면. 판정 오차 분포를 보여 주고 제안값 | — |
| 곡별 소리 오프셋 | `AudioWait`(곡별 + 장치별) | **두지 않는다**: 곡 오프셋은 곡 데이터의 진실(패키지 버전으로 고침)이지 사용자 설정이 아님. 반주만 옮기는 오프셋은 키음과 반주를 어긋나게 한다 | — |

## 8. 운영 (해당 없음 또는 나중)

계정·온라인·음성 대화·조명(RGB 8개 제조사)·업데이트 등 Qwilight의 [운영] 29개는 엔진 범위 밖이다. 필요해지면 따로 정한다.

## 9. 설정창 배치 (CP3 초안)

탭 = 위 묶음. 순서는 플레이 전에 자주 만지는 순서.

```
[규칙] [장비와 몸] [소리] [입력] [화면] [라이브러리] [엔진 ▸고급]
```

- **규칙 탭 상단에 "지금 규칙으로 낸 점수는 ___와 비교됨"** 표시 (규칙 해시). 프리셋 고르기가 탭의 첫 줄.
- **장비와 몸 탭**은 지연을 한 줄 그림으로 보여 준다: 누름 → (입력) → D → 키음 / 반주, 화면은 B. 숫자는 이 PC에서 잰 값.
- **엔진 탭**은 기본 숨김("고급 설정 보이기").
- 설정마다 범위 꼬리표(전역 / 장치별 / 키 모드별 / 프리셋)를 붙인다.
- CP3 설정창은 엔진의 D2D 화면 위에서 마우스·키보드로 조작한다(CP4에서 모양을 다시 입힌다).
