# 세미 게임 레이어 — 채보를 다른 언어로 보여 주는 화면

> 작성일 2026-10-09. 게임 개발 구상 문서 (이 저장소의 IIDX → BMS 변환 목적과는 별개).
> 전제: `만약 리듬게임을 개발한다면.md` (타이밍 설계), `곡 데이터 형식.md` (중간 형식).
> 표기: **(확인)** 실제 데이터로 확인, **(추정)** 검증하지 않은 판단, **(정책)** 정해서 쓰는 규칙.

---

## 0. 한 줄 정의

**채보와 판정이 진실이고, 세미 게임은 그 진실을 다른 언어로 그린 화면이다.**

플레이어가 누르는 것은 기어 화면과 똑같은 채보입니다. 다만 배경(또는 단독 화면)에서는 같은 입력이 장면 속 행동이 됩니다. 예: 3번 건반 단타 = 이 마디 동안은 점프키. 가시를 박자에 맞춰 넘어야 하고, 타이밍이 어긋나면 기어 화면에는 POOR, 세미 게임에서는 가시에 스쳐 데미지가 납니다.

---

## 1. 진실과 화면의 관계

```
진실:   채보(정규 ns) + 입력 → 판정 (PGREAT … POOR)        ← 하나뿐
기어:   화면 = f(표시 시각, 판정 상태)
세미:   화면 = g(표시 시각, 판정 상태, 장면 스크립트)       ← 같은 진실, 다른 그림
```

**규칙**
1. **세미 게임은 판정에 영향을 주지 않습니다.** 판정은 기존 판정 코어가 하고, 세미 게임은 결과를 읽기만 합니다.
2. **세미 게임에 물리 시뮬레이션을 돌리지 않습니다.** 점프·피격·이동은 모두 곡 시각에 맞춰 미리 짠 애니메이션이고, 판정 결과에 따라 변형을 고릅니다. 자기 물리가 생기면 두 번째 시계, 두 번째 진실이 됩니다.
3. **애니메이션 진행은 시각의 함수입니다.** 점프 진행 = `(표시 시각 − 입력 시각) / 점프 길이`. 렉 뒤 첫 프레임에도 캐릭터가 "지금 있어야 할 위치"에 그려집니다. 리플레이도 똑같이 재현됩니다.
4. **소리도 진실을 따릅니다.** 키음은 기존대로 채보가 정합니다. 세미 게임 효과음(착지음 등)은 선택 사항이고, 키음과 같은 오디오 예약 경로를 쓰며 음량 우선순위가 낮습니다.

## 2. 선례와 차별점

| 선례 | 닮은 점 | 다른 점 |
|---|---|---|
| 테트리스 DS | 플레이 뒤에서 다른 게임 장면이 진행 | 배경이 조작과 직접 연결되지 않음 |
| 놈 시리즈 (게임빌) | 단순 조작에 장애물이 의미를 줌 | 리듬 판정이 아님 |
| BIT.TRIP RUNNER | 박자에 맞춘 장애물 회피 러너 | 기어 화면이 없음, 레인 수가 적음 |
| 리듬 세상 | 판정은 리듬, 화면은 미니게임 | 세미 게임만 있고 채보 표기가 없음 |
| Muse Dash | 노트를 캐릭터 공격으로 포장 | 레인 구조 자체가 화면 |

**새로운 점**
1. **기어 화면과 세미 게임이 같은 판정을 동시에, 병렬로** 보여 줍니다.
2. **구간마다 건반의 의미가 바뀝니다.** 같은 입력이 문맥에 따라 다른 행동이 됩니다.
3. IIDX식 7키 + 스크래치 채보를 그대로 쓰므로, 기존 채보 자산(가져오기한 IIDX·BMS)에 장면만 얹을 수 있습니다.

## 3. 장면 문법

### 3-1. 두 단계 표현

| 단계 | 단위 | 내용 |
|---|---|---|
| **미시** | 노트 하나 | 작은 반응: 발걸음, 타격 불꽃, 발판 빛남. 모든 노트에 있음 |
| **거시** | 프레이즈 (1~4마디) | 의미 있는 장면: 가시 길, 무너지는 다리, 보스 공격. 일부 노트만 "의미 있는 행동"이 됨 |

모든 노트를 의미 있는 장애물로 만들 필요는 없습니다. 고밀도 구간은 거시 장면 하나 + 미시 반응으로 표현합니다(5장).

### 3-2. 노트 패턴 → 행동 (기본 어휘, 정책)

| 채보 패턴 | 기본 행동 | 비고 |
|---|---|---|
| 단타 (바인딩된 건반) | 그 건반의 행동 (점프, 슬라이드, 베기 …) | 구간마다 바인딩 |
| 2~3개 동시치기 | 합동 행동 (큰 점프, 양손 공격) | 손 모양이 행동 크기 |
| 롱노트 | 누르는 동안 지속 행동 (활공, 충전, 매달리기) | 끝 판정 = 착지·발사 |
| 스크래치 | 방향 전환, 대시, 베기 | IIDX에서 스크래치는 강한 악센트인 경우가 많음 (추정) |
| 연타·트릴 | 질주, 연속 타격 (거시 장면 하나로 묶음) | |
| 셋잇단·엇박 | 박자 간격이 다른 발판, 리듬이 다른 적 | 공간 간격 = 시간 간격 (4-2) |

### 3-3. 바인딩

- 바인딩 = 구간 동안 각 건반이 뜻하는 행동. 예: `{K3 = jump, K5 = slide, SC = dash}`.
- 바인딩이 없는 건반의 노트는 미시 반응만 합니다.
- 바인딩 변경은 반드시 예고합니다(4-3).

## 4. 공정성 규칙

세미 게임만 보고도 기어 화면만큼 정확히 칠 수 있어야 합니다. 세미 게임 단독 모드가 있다면 필수 조건입니다.

### 4-1. 정보가 같아야 함
- **모든 의미 있는 장면 행동은 실제 노트에 묶입니다.** 노트에 묶이지 않은 장애물은 두지 않습니다(장식은 장식으로 명확히 구분).
- 반대로 의미 있는 노트(바인딩된 건반의 노트)는 모두 장면에 보입니다.
- 세미 게임이 기어보다 정보를 더 주거나 덜 주면 안 됩니다.

### 4-2. 시간은 공간으로
- 캐릭터는 일정 속도로 진행하고(또는 화면이 일정하게 흐르고), 장애물은 **판정 시각에 캐릭터 위치에 오도록** 배치합니다. 장애물 사이 거리가 곧 시간 간격입니다.
- 이 "속도"는 기어의 노트 낙하 속도(하이스피드)와 같은 원리입니다. 사용자의 속도 설정이 두 화면에 함께 적용됩니다.
- BPM이 바뀌는 곡은 기어와 같은 스크롤 규칙(`scroll` 필드)을 씁니다. 화면 위 위치는 박 단위이고, 시각은 ns입니다.

### 4-3. 예고 시간
- 장애물은 **기어 화면에서 노트가 보이기 시작하는 시점과 같은 시점**에 보여야 합니다(같은 예고 시간). 판정 1박 전에 갑자기 나타나면 안 됩니다.
- 바인딩 변경은 **최소 1마디 전**에 예고합니다(정책): 건반 위 아이콘, 키 색, 화면 가장자리 표시. 처음 등장하는 바인딩에는 연습 마디(쉬운 노트 1~2개)를 둡니다.

### 4-4. 판정 → 연출

| 판정 | 연출 | 시점 |
|---|---|---|
| PGREAT | 깔끔한 성공 (최고 연출) | 입력 즉시 |
| GREAT | 아슬아슬한 성공 | 입력 즉시 |
| GOOD | 스침, 작은 데미지 | 입력 즉시 |
| BAD | 부딪힘 | 입력 즉시 |
| POOR (놓침) | 부딪힘, 큰 데미지 | **늦은 판정 창이 끝나고 watermark가 지난 뒤** |
| 빈 POOR (노트 없는 입력) | 헛동작 (헛점프, 헛베기) | 입력 즉시 |
| 롱노트 중간 해제 | 활공 중 추락 | 해제 판정 확정 시 |

- 놓침 확정은 늦은 판정 창의 끝인데, 그 순간이 마침 "장애물이 캐릭터를 지나가는 순간"입니다. 판정 확정 규칙(watermark)과 연출이 자연스럽게 일치합니다.
- 입력 직후에 "성공인지 실패인지" 판정이 나오므로, 점프 동작은 입력 시각부터 시작하고 결과에 맞는 궤적(정상·스침·충돌)을 고릅니다.

## 5. 밀도 대응

IIDX 채보는 순간적으로 초당 20개 이상의 노트가 나옵니다. 33131 SP ANOTHER도 약 2분에 789개입니다(확인).

| 구간 밀도 (정책, 박당 의미 있는 노트 수) | 표현 |
|---|---|
| 1개 이하 | 노트마다 개별 장애물·행동 |
| 2~3개 | 동시치기·짧은 패턴을 행동 하나로 (합동 공격, 연속 발판) |
| 4개 이상 | 거시 장면 하나 (질주, 연속 콤보) + 노트마다 미시 반응 |

- 밀도는 컴파일러가 계산해서 장면 생성기에 넘깁니다.
- 고밀도 구간에서도 **놓친 노트는 미시 반응으로 반드시 보입니다**(불꽃이 꺼짐, 발이 미끄러짐).

## 6. 데이터 형식

`곡 데이터 형식.md`의 시각 트랙을 확장한 **장면 트랙**입니다. 차분마다 하나씩 둡니다.

```toml
[scene]
chart = "SPA"
world = "spike_road"            # 장면 테마 (배경, 캐릭터, 오브젝트 세트)
lead  = "match_gear"            # 예고 시간 = 기어와 동일

[[scene.sections]]
id       = "intro"
measures = "0..0"
bind     = { SC = "dash" }

[[scene.sections]]
id       = "spikes"
measures = "1..1"
bind     = { K3 = "jump", K5 = "slide", K2 = "step_l", K6 = "step_r", K1 = "hop", K7 = "grab" }
announce = { at = "0:2", style = "key_icons" }   # 바인딩 예고 위치

[[scene.actions]]
note   = "SPA:m1b1:K3"          # 반드시 실제 노트에 묶임 (노트 ID)
action = "jump"
object = "spike"

[[scene.decor]]                 # 판정과 무관한 장식은 따로
at     = "1:0"
object = "torch"
```

### 6-1. 컴파일 검사 (모두 통과해야 장면을 쓸 수 있음)

| 검사 | 실패 시 |
|---|---|
| 모든 `actions`가 실제 노트에 묶였는가 | 오류 |
| 바인딩된 건반의 노트가 모두 장면에 보이는가 (자동 생성 포함) | 오류 |
| 바인딩 변경마다 예고가 최소 1마디 전에 있는가 | 오류 |
| 행동과 노트 종류가 맞는가 (롱노트 ↔ 지속 행동) | 오류 |
| 장애물 간 화면 거리가 시간 간격과 일치하는가 (스크롤 규칙) | 오류 |
| 밀도 규칙을 넘는 개별 장애물 배치 | 경고 |
| 같은 시각의 행동이 화면상 겹쳐서 구분이 안 되는가 | 경고 |

### 6-2. 자동 생성과 손 작업
1. **생성기**가 채보 패턴(3-2)과 밀도(5장)로 기본 장면을 만듭니다.
2. **제작자**가 섹션 단위로 덮어씁니다(바인딩, 테마, 거시 장면).
3. **검사기**(6-1)를 통과해야 저장됩니다.
4. **미리보기**: 기어와 세미 게임을 나란히 놓고 같은 시각으로 재생합니다.

가져온 IIDX·BMS 곡은 1단계만으로도 플레이 가능한 장면을 갖습니다.

## 7. 런타임

| 항목 | 방식 |
|---|---|
| 상태 | 판정 코어의 판정 스냅샷 + 장면 스크립트. 세미 게임 고유 상태는 판정 결과에서 다시 만들 수 있는 것만 |
| 애니메이션 | 곡 시각과 입력 시각의 함수. 프레임 누적 없음 |
| 렌더 | 기어 렌더와 같은 표시 시각 사용. 세미 게임이 늦어도 판정·소리는 영향 없음 |
| 무게 | 세미 게임 렌더가 프레임 예산을 넘으면 장식 세부 단계(LOD)를 낮춤. 기어 화면이 우선 |
| 리플레이 | 판정 기록만 있으면 세미 게임 화면이 똑같이 재현됨 |
| 오디오 | 세미 게임 효과음은 키음 예약 경로를 그대로 쓰고, 보이스 예산에서 가장 낮은 우선순위 |

## 8. 모드

| 모드 | 화면 | 대상 |
|---|---|---|
| 기어 + 배경 | 기어 앞, 세미 게임 뒤 (투명도 조절) | 숙련자, 관전·방송 |
| 세미 게임 단독 | 노트 없이 장면만 | 입문자. 노트의 의미를 행동으로 배움 |
| 분할 협동 | 한 명은 기어, 한 명은 세미 게임 화면. 레인을 나눠 연주 | 같은 진실을 공유하므로 동기화 문제 없음 |
| 바인딩 연습 | 한 구간 반복, 바인딩 표시 강조 | 바인딩 전환이 어려운 곡 연습 |

## 9. 예시: 33131 Ex-Otogibanashi SP ANOTHER 첫 4소절

실제 노트 배치 (확인, `../converter/tools/scene_export.py` 결과에서):

| 마디 | 박 | 노트 |
|---|---|---|
| 0 (6/4) | 4 | SC |
| 1 | 0 | K2 + K6 |
| 1 | 1 | K3 + K7 |
| 1 | 2 | K5 |
| 1 | 3 | K3 |
| 1 | 3.5 | K1 |
| 2 | 0, 0.75, 1.5, 2.25, 3 | K4, K2, K6, K4, K2 (3/16 간격 엇박) |
| 3 | 0, 1, 2, 3 | K3+K7+SC, K2+K6+SC, K1+K5+SC, K2+SC (매 박 스크래치 + 동시치기) |
| 3 | 3.33, 3.67 | K4, K6 (박 3부터 셋잇단 3연타 K2→K4→K6) |

장면 구성 (정책 예시):

| 마디 | 장면 | 바인딩과 행동 |
|---|---|---|
| 0 | **출발.** 6박짜리 도입 동안 캐릭터가 문 앞에서 숨을 고르고, 4박째 스크래치에 문을 박차고 달려 나감 | `SC = dash`. 마디 0의 2박째에 다음 바인딩(1마디) 예고 |
| 1 | **가시 길.** 0박 K2+K6 = 양발 착지, 1박 K3+K7 = 가시 위 큰 점프(점프 + 깃발 잡기), 2박 K5 = 낮은 가로대 밑 슬라이드, 3박 K3 = 가시 점프, 3.5박 K1 = 작은 돌 위 깡충 | 사용자 예시 그대로: K3 단타 = 점프. 늦으면 POOR + 가시에 스침 |
| 2 | **흔들리는 발판.** 가운데·왼쪽·오른쪽 발판이 3/16박 간격으로 놓여 있음. 발판 사이 거리가 일정하지 않아서, 엇박 리듬이 **발판 간격으로 눈에 보임** | `K4 = 가운데`, `K2 = 왼쪽`, `K6 = 오른쪽` 발판 디딤. 놓치면 발이 미끄러져 흔들림(작은 데미지) |
| 3 | **보스 대면.** 박마다 스크래치 = 베기, 함께 오는 동시치기 = 양손 타격. 3박째부터 K2→K4→K6 셋잇단 = 아래→가운데→위로 올라가는 3연타 마무리 | `SC = slash`, 동시치기 = `strike`, 셋잇단 = `combo_rise`. 매 박 스크래치는 바인딩 변경 없이 같은 행동 반복이라 읽기 쉬움 |

이 구간이 좋은 예인 이유:
- 1마디는 "단타·동시치기 = 개별 장애물" (5장 밀도 1개 이하)
- 2마디는 "엇박 = 공간 간격" (4-2)
- 3마디는 "반복 패턴 + 마무리 콤보 = 거시 장면" (5장 밀도 2~3개)

이 세 가지가 연달아 나옵니다.
