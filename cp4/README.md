## CP4가 답할 질문

> CP3의 엔진 위에, **화면의 모든 텍스트·영상·이미지·도형 자리를 사용자가 자기 에셋으로 연결할 수 있는** 게임을 만들 수 있는가 — 화면이 판정·소리의 약속(PERFECT 키음 = 반주, 결정성)을 하나도 건드리지 않으면서, 모듈 경계가 분명해서 렌더러·스킨·규칙·화면을 서로 모르고 바꿀 수 있게.

CP4가 끝나면 답해져 있어야 할 것:

1. **화면 도메인**: 화면·층·요소·자리·값·사건·시계·스킨·에셋의 이름과 관계가 문서와 코드에서 같은가 (`화면_도메인.md` 확정).
2. **스킨**: 기본 스킨 하나로 모든 화면의 모든 자리가 그려지고, 사용자 스킨이 자리 단위로 바꿔 끼울 수 있는가. 스킨이 자기 옵션을 정의하는가.
3. **곡 그래픽**: BGA 영상·이미지 BGA·자켓이 곡 시각에 맞게 나오는가(화면 시계 = 청취 곡 시각 + B).
4. **규칙**: 판정 창·게이지·롱노트 규칙·빈 누름 판정을 프리셋으로 바꾸고, 점수가 규칙 해시로 갈리는가.
5. **경계**: 렌더러(wgpu)·스킨·화면·세션·플랫폼이 각자 인터페이스로만 이어지는가 — 화면을 멈춰도(렌더 정지 주입) 판정·소리가 그대로인가.

## 1. 원칙 (CP2·CP3에서 이어받음)

- **진실은 엔진, 화면은 읽기만.** 화면은 판정 스레드가 게시한 스냅샷과 확정된 사건만 읽는다. 화면이 늦거나 멈춰도 판정·키음·반주는 그대로(CP2 렌더 정지 주입으로 확인한 성질을 CP4에서도 시험으로 유지).
- **실시간 스레드 무할당·무잠금.** CP3에서 넘어온 예외(판정 스레드의 화면 상태 `try_lock`)를 CP4 첫 단계에서 없앤다.
- **데이터로 정의.** 화면 배치·규칙·스킨 옵션은 데이터(파일)다. 코드에 하드코딩하는 것은 "자리 목록"과 "값·사건 목록"(엔진이 제공하는 계약)뿐.
- **결정성.** 같은 리플레이 = 같은 판정·같은 소리. 화면은 결정성 대상이 아니지만, 같은 스냅샷 시퀀스면 같은 그림을 그린다(스킨 시험용).
- **CP4 범위에서 엔진 이름은 문서용 "Unison"**. 정식 이름·확장자는 ⚑.

## 3. 구조 — 모듈과 경계

```
  ┌──────────── app (실행 파일: 묶기만) ────────────┐
  │                                                 │
  │  scene (화면 상태 머신·입력 라우팅·전환)          │
  │     │ 값·사건 읽기            │ 그리기 목록       │
  │     ▼                         ▼                   │
  │  session (PlaySession)     skin (배치 해석·      │
  │  오디오·입력·판정 스레드     바인딩·애니메이션)   │
  │  스냅샷·사건 게시(무잠금)     │                   │
  │     │                         ▼                   │
  │     ▼                      render (인터페이스)    │
  │  engine (소리·판정·규칙)       └ wgpu 백엔드       │
  │     │                            영상 디코더       │
  │     ▼                                             │
  │  track (형식·컴파일러·색인)   platform (창·입력·  │
  │                               오디오 장치: Windows)│
  └─────────────────────────────────────────────────┘
```

| 크레이트 (제안) | 하는 일 | 모르는 것 |
|---|---|---|
| `track` | 형식·컴파일러·묶음·색인 (CP3 그대로 + 그래픽 묶음·선곡 자원) | 엔진·화면 |
| `engine` | 로더·믹서·판정·규칙(데이터)·미리보기 저장소·보정 계산·**규칙 프리셋·정책 자리** | 창·장치·화면 |
| `platform` | 창·메시지(창별 이벤트)·Raw Input·WASAPI/ASIO·시계 | 게임 규칙·화면 |
| `session` | `PlaySession`: 오디오·입력·판정 스레드를 띄우고 묶음, **판정 스냅샷·사건 링(무잠금)**, 세션 끝, 결과 구조체, 기록·리플레이 | 그리기 |
| `skin` | 스킨 형식 읽기·검사, 자리 연결, 바인딩·조건·애니메이션 계산 → **그리기 목록**(렌더러 중립) | 렌더 API·게임 상태 내부 |
| `render` | 렌더러 인터페이스(그리기 목록 → 화면, 화면 시각 보고), wgpu 백엔드, 글꼴·그림·영상 텍스처 | 게임·스킨 의미 |
| `scene` | 화면 상태 머신(시작·선곡·결정·플레이·결과·설정·보정), 입력 라우팅, 값·사건 조립 | 렌더 API |
| `app` | 위를 묶는 실행 파일, 명령줄 | — |

- **경계의 데이터**: `session` → `scene`: 스냅샷(`PlaySnapshot`: 점수·게이지·노트 진행·눌림)과 사건 링(`JudgeEvent` 등). `scene` → `skin`: 값 표·사건 목록·시계. `skin` → `render`: 그리기 목록(글자·그림·영상·도형 명령 + 변환·혼합·잘라내기).
- **바꿔 끼우기 시험**: 렌더러를 "기록만 하는 가짜 렌더러"로 바꿔도 스킨·화면 시험이 돌고, 스킨을 바꿔도 세션 시험이 그대로여야 한다.

## 6. 열린 질문 ⚑ (사용자 판단)

1. 스킨 표현 방식: 선언형(TOML/JSON 배치 + 작은 식) / 스크립트(Lua 등) 포함.
2. 기존 스킨(LR2·beatoraja·Qwilight) 불러오기를 목표로 할지, 한다면 언제.
3. 가상 해상도·종횡비 정책.
4. 영상 디코더 선택.
5. 세미 게임 레이어를 CP4에 넣을지.
6. 렌더러: wgpu 하나로 갈지, 지금의 D3D11 단순 렌더러를 진단용으로 남길지.
7. 엔진 정식 이름을 CP4 안에서 정할지.
