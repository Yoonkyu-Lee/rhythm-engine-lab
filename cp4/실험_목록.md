# CP4 전에 답할 질문과 실험

> 작성일 2026-10-17. CP4 계획(`README.md` 초안)은 **보류** — 아래 질문에 실험으로 답한 뒤 계획을 세운다.
> 형식: 질문 → 왜 중요한가 → 실험(무엇을 재나) → 결과로 정하는 것. 🧑 = 사용자가 있어야 하거나 장비가 필요한 실험.

---

## A. 렌더러 — 무엇으로 그리고, 화면에 나간 시각을 알 수 있나

> 지금(CP3): Direct3D 11 + DXGI 플립 스왑체인(대기 가능, 프레임 지연 1) 위에 **Direct2D로 꽉 찬 사각형과 DirectWrite 글자 두 가지만** 그린다(`../cp3/crates/game/src/render.rs`). 그림·영상·선·원·그라데이션·텍스처는 없고, 기어·노트·게이지·그래프가 모두 사각형이다. 화면 시각은 DXGI 프레임 통계.

**A1. 화면에 실제로 나간 시각(present 시각)을 프레임마다 알 수 있나 — API별로?**
- 왜: 노트가 판정선에 닿는 화면 시각을 소리에 맞추는 것(오프셋 B, 화면 싱크)이 CP4의 약속이다. 시각을 모르면 잴 수도 맞출 수도 없다.
- 실험: 같은 단순 장면을 Direct3D 11(지금, DXGI 프레임 통계·대기 가능한 스왑체인), Direct3D 12, wgpu(D3D12 백엔드)로 그리고, 프레임마다 "present 호출 → 실제 화면 갱신 번호·시각"을 얼마나 정확히 얻는지 비교. 60·144 Hz, 창 모드·전체 화면·경계 없는 창.
- 정하는 것: 렌더러 백엔드, 화면 시계의 정의.

**A2. 지연을 줄이는 출력 방식은 무엇이 가능하고 효과가 얼마인가?**
- 왜: 리듬게임은 입력 → 화면 지연이 체감 품질이다(소리는 CP2·CP3에서 해결).
- 실험: 플립 모델·tearing 허용·대기 가능한 스왑체인·전체 화면 독점·프레임 지연 1 설정별로, 렌더 → present → 화면 갱신까지의 시간(A1의 방법) 분포. API별로 쓸 수 있는 조합 표.
- 정하는 것: 기본 출력 모드와 설정 화면의 "그래픽" 항목.

**A3. 화면 시각을 물리적으로 검증할 수 있나? 🧑**
- 왜: A1은 OS·드라이버가 말하는 시각이다. 모니터 자체 지연(수 ms~수십 ms)은 PC가 볼 수 없다(`../design/만약 리듬게임을 개발한다면.md` 12-2).
- 실험 후보: (a) 광센서(포토다이오드)를 화면에 대고 오디오 입력(Loopback 옆 입력 채널)으로 녹음해 소리와 빛을 같은 장치 시계로 비교, (b) 고속 촬영(휴대폰 240 fps)으로 화면과 스피커 LED·소리 비교, (c) 사람 보정(화면으로 맞추기)의 반복성.
- 정하는 것: 화면 싱크의 완료 기준을 어디까지 물리로 확인할지. (a)는 장비가 필요 — 사용자 판단.

**A4. 스킨이 요구할 그리기 양을 어떤 백엔드가 감당하나?**
- 왜: 기어·노트·이펙트·숫자·BGA·배경 영상을 동시에 그린다. 고밀도 BMS는 화면에 노트 수백 개.
- 실험: 스프라이트 1천·1만·5만 개, 혼합 방식 섞기, 글자 2천 자, 영상 2개 동시(BGA + 배경)를 4K·144 Hz에서 그려 프레임 시간·CPU 사용·GPU 사용. 지금 D3D11 + Direct2D 단순 렌더러와 일괄 그리기(sprite batch) 구현 비교.
- 정하는 것: 렌더러 구조(일괄 그리기 필요 여부), 스킨 그리기 목록 상한.

**A5. 다국어 글자(한·중·일·라틴, 장식 글꼴)를 어떻게 그리나?**
- 왜: 곡 제목·아티스트는 BMS에서 일본어가 많고, 스킨은 장식 글꼴을 쓴다.
- 실험: DirectWrite → 텍스처, 글리프 아틀라스(미리 구움) 두 방식으로 870곡 목록을 스크롤할 때 프레임 시간·메모리·글자 품질, 글꼴에 없는 글자의 대체 동작.
- 정하는 것: 글자 경로, 스킨 글꼴 형식.

## B. 영상(BGA) — 무엇으로 디코딩하고 곡에 어떻게 맞추나

**B1. 우리 라이브러리의 영상은 어떤 형식인가?**
- 왜: 디코더가 지원해야 할 범위가 정해진다.
- 실험: BMS(가진 팩 전체)·IIDX·DJMAX 영상 파일의 컨테이너·코덱·해상도·fps·길이 통계(읽기만, 파일 머리 분석). BMS는 mpg(MPEG-1)·avi(여러 코덱)·wmv·mp4가 섞여 있을 것으로 예상(추정).
- 정하는 것: 지원 목록, 변환(재인코딩) 필요 여부 — CP3 README 2-1의 "영상 변환 여부".

**B2. Media Foundation과 FFmpeg 중 무엇이 그 형식을 다 디코딩하나, 비용은?**
- 실험: B1의 표본 각 형식을 두 디코더로 열어 성공률, 하드웨어 디코딩 여부, 프레임당 CPU·GPU 시간, 첫 프레임까지 시간, 탐색(seek) 정확도·시간. D3D11 텍스처로 바로 받기(복사 없음) vs CPU 복사.
- 정하는 것: 디코더, 라이선스·배포 크기, 렌더러와의 연결 방식(A와 함께).

**B3. BGA를 곡 시각에 프레임 단위로 맞출 수 있나?**
- 왜: BGA는 곡 시각에 묶여 있다. 오디오 정지·콘텐츠 건너뜀·탐색·버퍼링 뒤에도 맞아야 한다.
- 실험: 화면 시계(청취 곡 시각 + B)로 "지금 보일 프레임"을 고르는 방식으로 재생하며, 영상 시계와 곡 시계의 차를 프레임마다 기록. 렉 주입(오디오·화면·디코더 정지) 뒤 다시 맞는 시간, 탐색 뒤 첫 프레임 지연.
- 정하는 것: BGA 재생 정책(프레임 버림·반복·건너뛰기), 미리 디코딩할 양.

**B4. 이미지 BGA(BMS #BMP 그림 교체)는 얼마나 무거운가?**
- 실험: BMS 표본의 #BMP 수·크기·교체 빈도, 전부 미리 올릴 때 메모리·로딩 시간 vs 필요할 때 올리기.
- 정하는 것: Track 그래픽 묶음 형식과 로딩 정책.

## C. 화면 도메인 — 우리 이름으로 다른 게임의 화면을 다 표현할 수 있나

**C1. 다른 게임·구동기의 화면 요소를 우리 도메인(화면·층·요소·자리·값·사건)으로 옮길 수 있나?**
- 왜: 사용자가 원하는 "자리마다 마음대로 연결"이 실제 스킨들의 요구를 덮어야 한다.
- 실험: IIDX·DJMAX 플레이·선곡·결과 화면(스크린샷·CP0 분석), beatoraja·LR2·Qwilight 스킨 형식의 요소 종류·타이머·조건 목록을 모아 `화면_도메인.md`의 표로 하나씩 대응. 대응 안 되는 것 목록.
- 정하는 것: 요소 종류·자리 목록·사건 목록 확정, 빠진 개념(예: 마스크, 파티클, 셰이더 효과).

**C2. 선언형 배치로 충분한가, 스크립트가 필요한가?**
- 실험: C1에서 가장 복잡한 화면 셋(예: DJMAX 플레이 기어 연출, beatoraja 선곡 화면, IIDX 결과)을 선언형 시안(배치 + 작은 식)으로 실제로 적어 보고, 적을 수 없는 것을 센다.
- 정하는 것: 스킨 표현 방식(선언형 / 식 범위 / 스크립트).

**C3. 기존 스킨을 불러올 가치가 있나?**
- 실험: beatoraja·LR2·Qwilight 스킨 하나씩을 C1 대응표로 변환할 때 손실 목록(사람이 손으로 대응해 봄).
- 정하는 것: 변환기를 만들지, 언제.

## D. 경계 — 화면이 판정·소리를 건드리지 않게 나눌 수 있나

**D1. 판정 스냅샷을 무잠금으로 게시하는 비용은?**
- 실험: 지금 `try_lock` + 전체 `JudgeView` 복제 vs 삼중 버퍼 스냅샷 vs 사건 링(차이만)을 16레인·고밀도 차분에서 비교: 판정 스레드 처리 시간 분포, 화면이 받는 지연, 메모리.
- 정하는 것: `session` → `scene` 경계의 자료 구조.

**D2. 화면이 멈춰도(렌더 정지·스킨 다시 읽기·영상 디코딩 정지) 판정·소리가 그대로인가?**
- 실험: CP2 렌더 정지 주입을 새 구조에서, 스킨 다시 읽기·영상 디코더 정지를 더해 싱크 측정(3-5 분석기).
- 정하는 것: 모듈 경계가 약속을 지키는지 — CP4 각 단계의 회귀 시험.

**D3. 크로스플랫폼이 목표인가?** — **결정 (2026-10-17, 사용자): 일단 Windows 기준.**
- 오디오(WASAPI·ASIO)·입력(Raw Input)이 Windows 전용이므로 화면도 Windows API를 바로 써도 된다. A1에서 wgpu는 "Direct3D를 직접 쓸 때보다 나은 점이 있는가"를 보는 비교 후보로만 둔다.

## E. 자원 — 에셋이 많아질 때

**E1. 스킨·곡 그래픽의 로딩·메모리 예산은?**
- 실험: 기본 스킨 시안(그림 수백 장)·자켓 870장·BGA 영상을 올릴 때 VRAM·시스템 메모리·로딩 시간, 선곡 화면 스크롤 중 자켓 지연.
- 정하는 것: 선곡 자원 색인 형식, 에셋 캐시·예산(CP3 소리 예산 2 GB와 별도).

**E2. 스킨을 바꾸거나 다시 읽을 때 얼마나 걸리나?**
- 실험: 에셋 해시 캐시 유무에 따라 스킨 전환 시간.
- 정하는 것: 다시 읽기 지원 범위(플레이 중 불가 등).
